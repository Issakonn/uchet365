# Учет-365 — полноценная бесплатная версия на Cloudflare Pages + D1

Этот проект уже подготовлен как **полноценная система**, а не просто HTML-файл.

Что сделано:

- сайт остаётся статическим и быстро открывается;
- серверная часть вынесена в `functions/api/[[route]].js`;
- коды консультаций теперь **реально заканчиваются на сервере**, а не только в браузере;
- админка защищена паролем `ADMIN_TOKEN`;
- тексты и картинки сохраняются в общей базе данных, а не в localStorage конкретного браузера;
- публичный сайт больше не получает весь список кодов, поэтому решение стало безопаснее.

---

## Архитектура

- **Cloudflare Pages** — хостинг сайта
- **Cloudflare Pages Functions** — серверные API-маршруты `/api/...`
- **Cloudflare D1** — база данных SQLite в облаке

Это один из самых аккуратных бесплатных вариантов для такого проекта.

---

## Структура

- `index.html` — главная страница
- `admin.html` — защищённая админ-панель
- `js/main.js` — логика сайта
- `js/admin.js` — логика админки
- `js/site-db.js` — работа с контентом и изображениями
- `functions/api/[[route]].js` — серверные API
- `schema.sql` — создание таблиц базы
- `wrangler.toml` — конфигурация Cloudflare

---

## Что важно понять

Изначальный проект был не полноценным серверным сайтом, а фронтендом, который ожидал некий внешний API `tables/...`.

Из-за этого:

- если такого сервера нет — коды не работают как общая система;
- localStorage работает только в одном браузере;
- коды могли не «исчерпываться» глобально;
- админка была открыта без защиты.

В этой версии это исправлено.

## Как опубликовать бесплатно

### 1. Создать аккаунт Cloudflare
Если аккаунта нет — зарегистрируйтесь на Cloudflare.

### 2. Создать базу D1
В панели Cloudflare:

1. `Storage & Databases` → `D1 SQL Database`
2. Создайте базу, например `uchet365-db`
3. Скопируйте `database_id`

### 3. Создать таблицы
Откройте SQL-консоль базы и выполните содержимое файла `schema.sql`.

### 4. Прописать database_id
В файле `wrangler.toml` замените:

`PASTE_YOUR_D1_DATABASE_ID_HERE`

на настоящий `database_id` вашей базы.

### 5. Задать пароль админа
В Cloudflare Pages / Workers добавьте секрет:

- имя: `ADMIN_TOKEN`
- значение: ваш сложный пароль

Пример хорошего пароля:

`Uchet365_Admin_2026_Strong!`

### 6. Загрузить проект в GitHub
Создайте репозиторий и загрузите туда содержимое этой папки.

### 7. Подключить Pages
В Cloudflare:

1. `Workers & Pages` → `Create application`
2. `Pages` → `Connect to Git`
3. Выберите репозиторий
4. Build command можно оставить пустой
5. Output directory: `.`

### 8. Привязать D1 к Pages-проекту
В настройках Pages проекта подключите D1 binding:

- binding name: `DB`
- database: ваша D1 база

### 9. Открыть сайт
После деплоя вы получите адрес вида:

`https://your-project.pages.dev`

Админка будет доступна по адресу:

`https://your-project.pages.dev/admin.html`

## Как пользоваться после публикации

### Публичный сайт
- показывает тексты и картинки из базы;
- показывает остаток кодов;
- при нажатии на кнопку консультации резервирует код на сервере.

### Админка
- запрашивает пароль администратора;
- позволяет добавлять и удалять коды;
- позволяет вернуть использованный код обратно;
- позволяет менять тексты сайта;
- позволяет менять ссылки на изображения.

---

## Безопасность

В этой версии сделаны важные улучшения:

1. **Список кодов не отдаётся публичному сайту**
2. **Код выдаётся через отдельный серверный маршрут**
3. **Админка защищена паролем**
4. **Тексты и картинки редактируются только после авторизации**

Но дополнительно рекомендую:

- не давать ссылку на `admin.html` посторонним;
- использовать длинный пароль;
- периодически менять пароль;
- при желании позже добавить Cloudflare Access поверх админки.

## Что можно улучшить потом

## Локальная логика

В браузере оставлен мягкий fallback для текста и изображений, чтобы страница не ломалась при локальном открытии файлов.

Но **полноценный режим** работает именно после публикации в Cloudflare с подключённой D1 и секретом `ADMIN_TOKEN`.
